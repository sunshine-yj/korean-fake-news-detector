# 파이프라인

n8n(Docker) 기반으로 구현한 4개의 워크플로. 데이터 수집부터 가짜뉴스 생성, 실시간 추론 서빙까지를 담당한다.

> ⚠️ **이용 제한**
> 본 워크플로는 가짜뉴스 **탐지 모델 연구**를 위한 학습 데이터 구축 목적으로 작성되었다.
> 특히 `fakenews-generator`는 DB 연결만 변경하면 허위 기사를 대량 생성할 수 있으므로,
> 비상업적 연구·교육 목적 외의 사용을 금한다. 생성물을 실제 유통해서는 안 된다.

---

## 1. 워크플로 개요

| 파일 | 역할 | 트리거 |
|---|---|---|
| `rss-collector.json` | RSS 피드 기반 실제 기사 수집 | 스케줄 (매일 06시) |
| `api-collector.json` | 네이버 뉴스 API 기반 실제 기사 수집 | 스케줄 |
| `fakenews-generator.json` | 수집 기사 기반 가짜뉴스 생성 | 수동 실행 |
| `extension-inference.json` | 크롬 확장 요청 처리 및 판정 반환 | Webhook (POST) |

### 전체 흐름

```
[수집]                          [생성]                    [서빙]

rss-collector ─┐
               ├→ MySQL(articles) ─→ fakenews-generator ─┐
api-collector ─┘         │                               │
                         │                               ↓
                         └───────────── 학습 데이터 ──→ KPF-BERT 앙상블
                                                          ↑
                     Chrome Extension → extension-inference → FastAPI
```

## 2. rss-collector

5개 언론사(연합뉴스·SBS·동아일보·한겨레·JTBC)의 RSS 피드에서 기사 목록을 받아, 원문 페이지를 크롤링해 본문을 추출한다.

### 구조

```
스케줄 트리거 (매일 06시)
   ↓ 13개 RSS 피드 병렬 요청
RSS 병합 → RSS 합치기 (<item> 블록 재조합)
   ↓
XML 파싱 → 정제 (언론사별)
   ↓
1개씩 처리 (SplitInBatches)
   ↓ 6초 딜레이
원문 페이지 크롤링
   ↓
언론사 분류 (Switch, URL 도메인 기준)
   ↓
HTML 추출 → 병합·정제 (언론사별 CSS 셀렉터)
   ↓
가드레일 (길이 100자 미만 제외, 21,000자 절단)
   ↓
중복 URL 체크 → 기사 저장
```

### 설계 의도

**언론사별 분기 처리** — 각 언론사의 HTML 구조가 달라 단일 셀렉터로는 본문 추출이 불가능했다. URL 도메인으로 분기해 각각 다른 셀렉터를 적용한다.

| 언론사 | CSS 셀렉터 |
|---|---|
| 연합뉴스 | `div.story-news p` |
| SBS | `div.text_area` |
| 동아일보 | `section.news_view` |
| 한겨레 | `div.article-text` |
| JTBC | (HTML 내 `articleInnerTextContent` JSON 필드를 정규식 추출) |

JTBC는 본문이 서버 렌더링 HTML이 아니라 페이지 내 JSON 데이터에 들어 있어, CSS 셀렉터가 아닌 정규식 방식을 사용했다.

**요청 간 6초 지연** — 언론사 서버에 부하를 주지 않기 위해 기사 1건마다 6초 대기 후 크롤링한다.

**인사·부고 기사 제외** — 전보·인사발령·부고·별세 등 19개 키워드를 포함한 제목은 수집 대상에서 제외한다. 정형화된 짧은 문서라 조작 대상으로 부적합하기 때문이다.

**본문 정제** — 기자 바이라인, 이메일, 저작권 고지, 사진 캡션(`▲`, `◇`) 등을 정규식으로 제거한다.

## 3. api-collector

네이버 뉴스 검색 API로 키워드 기반 수집을 수행한다. RSS가 최신 기사만 제공하는 한계를 보완하기 위해 도입했다.

### 구조

```
스케줄 트리거
   ↓
키워드 × 페이지 조합 생성 (45키워드 × 5페이지 = 225 요청)
   ↓ 3초 딜레이
네이버 뉴스 API 호출
   ↓
기사 정제 (허용 도메인 필터링)
   ↓
(이후 rss-collector와 동일한 크롤링·추출·저장 경로)
```

### 키워드 설계

| 카테고리 | 키워드 (15개씩) |
|---|---|
| 정치 (1) | 대통령, 국회, 여당, 야당, 선거, 정당, 국무총리, 외교, 국방, 헌법, 탄핵, 공천, 법안, 의원, 입법 |
| 경제 (2) | 주식, 부동산, 금리, 물가, 환율, 코스피, 수출, 무역, 기업, 취업, 실업, 한국은행, 재정, 세금 |
| 사회 (3) | 사건사고, 범죄, 재난, 교육, 복지, 의료, 저출생, 청년, 주거, 환경, 노동, 인권, 이민, 사회갈등 |

**허용 도메인 제한** — 네이버 API는 다양한 매체를 반환하므로, RSS 수집과 동일한 5개 언론사만 통과시켜 데이터 출처를 일관되게 유지했다.

### 인증

`X-Naver-Client-Id`, `X-Naver-Client-Secret` 헤더가 필요하다. 공개 저장소에는 값을 포함하지 않으므로, 실행 시 [네이버 개발자센터](https://developers.naver.com/)에서 발급받은 값을 직접 입력해야 한다.

## 4. fakenews-generator

수집된 실제 기사를 원본으로 5가지 조작 유형 중 하나를 적용해 가짜 기사를 생성한다. 본 연구의 핵심 파이프라인이다.

### 구조

```
수동 실행
   ↓
MySQL: 실제 뉴스 조회 (미사용 원본 1,000건, RAND())
   ↓
Loop: 기사 순회
   ↓
프롬프트 균형 조절 (유형별 현재 건수 집계)
   ↓
역할 부여 (최소 건수 유형 선택 → 프롬프트 주입)
   ↓
① 가짜 본문 생성 LLM (GPT-5-mini)
   ↓
⑦ 생성 결과 검증
   ↓
⑧ IF: 유효? ──(실패)──→ 재시도 대기 30초 → 재생성
   ↓ (성공)
② 가짜 제목 생성 LLM
   ↓
기사 저장
```

### 유형 균형 유지

라운드로빈이 아니라 **DB의 실제 유형별 건수를 매 반복마다 조회**해 가장 적은 유형을 선택한다. 생성 실패로 특정 유형이 누락되어도 자동으로 보정된다.

```sql
SELECT prompt_type, COUNT(*) AS cnt
FROM articles WHERE is_fake = 1
GROUP BY prompt_type;
```

### 생성 결과 검증

| 검사 | 내용 |
|---|---|
| 거부 응답 | `도와드릴 수 없`, `죄송합니다`, `악용될 위험`, `정책상` 포함 여부 |
| 동일성 | 원문과 완전히 같은지 |
| 길이 | 원문의 60% 이상인지 |
| 유형별 | **유형 1만** — 숫자 집합이 실제로 변경되었는지 |

### 조작 유형

프롬프트 전문과 설계 근거는 [`prompts/`](prompts/) 참조.

| # | 유형 | 선행연구 |
|---|---|---|
| 1 | 수치 변경 | O |
| 2 | 고유명사 치환 | O |
| 3 | 출처 익명화 | **X (본 연구)** |
| 4 | 인과 왜곡 | O |
| 5 | 동사 반전 | **X (본 연구)** |

## 5. extension-inference

크롬 확장 프로그램 'AI 뉴스 정제기'의 백엔드 경로. 사용자가 열람 중인 기사 URL을 받아 판정 결과를 반환한다.

### 구조

```
Webhook (POST, url)
   ↓
HTTP Request — 대상 페이지 HTML 다운로드
   ↓
범용 HTML 추출 (다중 셀렉터 시도)
   ↓
1차 전처리 (정규식)
   ↓
전처리 LLM (Gemini 2.5 Flash Lite)
   ↓
JSON 파싱
   ↓
FastAPI /predict (127.0.0.1:5000)
   ↓
결과 정리 → Webhook 응답
```

### 2단 전처리를 채택한 이유

수집 파이프라인과 달리 **어떤 언론사 페이지가 들어올지 미리 알 수 없다.** 따라서 언론사별 셀렉터 분기가 불가능하다.

1. **1차 (정규식)** — 범용 셀렉터로 후보 영역을 넓게 잡은 뒤, 알려진 노이즈 패턴(광고, 저작권 고지, 기자 바이라인, 포털 안내문, 중복 문장)을 규칙 기반으로 제거한다.
2. **2차 (LLM)** — 규칙으로 잡히지 않는 잔여 노이즈를 언어모델이 판단해 걸러낸다. 새로운 내용을 생성하지 않도록 프롬프트에서 명시적으로 제약했다.

규칙 기반만으로는 사이트마다 다른 노이즈를 모두 처리할 수 없고, LLM만 쓰면 비용과 지연이 커진다. 두 방식을 직렬로 배치해 균형을 맞췄다.

### 응답 형식

```json
{
  "title": "정제된 제목",
  "content": "정제된 본문",
  "predicted_class": 0,
  "confidence": 0.97
}
```

## 6. 실행 방법

### 6.1 Import

n8n 관리 화면 → Workflows → Import from File → `workflows/` 내 JSON 선택

### 6.2 Credential 설정

공개 저장소에는 인증정보를 포함하지 않는다. Import 후 다음을 직접 등록해야 한다.

| Credential | 사용 워크플로 |
|---|---|
| MySQL | rss-collector, api-collector, fakenews-generator |
| OpenAI API | fakenews-generator |
| Google Gemini (PaLM) API | extension-inference |
| 네이버 Client ID / Secret | api-collector (HTTP 헤더에 직접 입력) |

### 6.3 실행 순서

```
1. rss-collector / api-collector 실행 → 실제 기사 확보
2. fakenews-generator 실행 → 가짜 기사 생성
3. 학습 및 평가 (src/ 참조)
4. extension-inference 활성화 → 크롬 확장 연동
```

## 7. 알려진 한계

파이프라인 구현상의 제약으로, 수집·생성된 데이터에 다음 특성이 존재한다. 데이터 해석 시 고려가 필요하다.

**① 카테고리 정보 소실 (rss-collector)**
정치·경제·사회 피드를 각각 수집하지만, `RSS 합치기` 단계에서 `<item>` 블록을 하나로 병합하면서 출처 섹션 정보가 사라진다. 결과적으로 RSS 경로로 수집된 기사의 `category_id`는 모두 동일한 값으로 저장된다. api-collector는 키워드 카테고리를 유지하므로 이 문제가 없다.

**② source_id 매핑 불일치**
두 수집 워크플로가 서로 다른 `source_id` 값을 사용한다. 특히 값 `6`이 rss-collector에서는 한겨레, api-collector에서는 SBS를 가리켜 혼재가 발생한다. 언론사별 집계 시 `source_id`가 아닌 **URL 도메인 기준**으로 재집계할 것을 권한다.

**③ JTBC 노드 참조 오류 (api-collector)**
`추출 및 병합 — JTBC` 노드가 이 워크플로에 존재하지 않는 노드명(`1개씩 처리1`)을 참조한다. rss-collector에서 복제하며 발생한 것으로, API 경로를 통한 JTBC 기사 수집이 실패했을 가능성이 있다.

**④ 스케줄 설정 불일치 (api-collector)**
트리거 노드명은 "매일 06시 실행"이나 실제 설정은 분 단위 반복이다.

**⑤ 원본-가짜 연결 미기록 (fakenews-generator)**
INSERT 시 `origin_article_id`를 저장하지 않아 가짜 기사와 원본의 직접적 참조가 없다. 가짜 기사가 원본의 `url`을 복사해 저장하므로 URL을 통한 간접 연결만 가능하다.

**⑥ 중복 원본 선택 가능성 (fakenews-generator)**
미사용 원본을 조회하는 SQL이 기본키끼리 자기조인(`a.article_id = b.article_id`)하도록 작성되어, 의도한 중복 배제가 동작하지 않는다. 동일 원본에서 가짜가 복수 생성되었을 가능성이 있다. 실제 발생 여부는 URL 기준 집계로 확인 가능하다.

**⑦ 유형별 검증 부분 적용 (fakenews-generator)**
생성 결과 검증에서 유형별 실질 검사가 유형 1에만 적용된다. 유형 2~5는 조작이 실제로 반영되었는지 확인 없이 통과한다.

**⑧ 발행일 폴백**
RSS `pubDate`가 없는 경우 수집 시각을 `published_at`으로 저장한다.

**⑨ 본문 길이 절단**
MySQL TEXT 용량(65,535 bytes)과 한글 3바이트 인코딩을 고려해 본문을 21,000자에서 절단한다.

**⑩ SQL 파라미터 미바인딩**
중복 URL 체크 쿼리가 URL 값을 문자열로 직접 연결한다. 외부 입력이 쿼리에 삽입되는 구조이므로, 재사용 시 파라미터 바인딩으로 변경할 것을 권한다.

**⑪ 재시도 횟수 무제한**
생성·전처리 LLM 실패 시 대기 후 재시도하는 루프에 상한이 없다.
